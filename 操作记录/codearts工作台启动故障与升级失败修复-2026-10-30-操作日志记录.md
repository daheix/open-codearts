## 二、故障现象与定位过程

### 2.1 现象
- 工作台 GUI 本体能起进程，但每个会话报错弹窗，标题"无法启动会话"，正文"无法找到 codearts cli（~/.codeartsdoer/installers/bin/codearts）"。
- 本机为 Wayland 会话（XWayland `:0`）；工作台静态 Qt6 仅带 xcb 平台插件，运行时打印 `Could not find the Qt platform plugin "wayland"` 后自动落到 xcb —— 属正常路径，非故障原因（已排除）。
- 排查中发现：`~/.codeartsdoer/installers/bin/` 下**没有 `codearts`，只有 `codearts.delete`**（161 MB，10-24 23:52）。

### 2.2 根因（证据链）
1. **升级流程"先改名后部署"**。10-29 23:42-23:43 内核日志（`cli-data/log/kernel-...2026-10-29T234055-3098810-0.log`）完整记录：
   - 23:41 查到新版本 26.10.13（`ide.cn-north-4.myhuaweicloud.com/v1/release-info/latest`）；
   - 23:42:26-23:43:17 下载 73,160,786 B 至 `/tmp/codearts-install-26.10.13`，哈希校验通过；
   - 23:43:18 `renaming current exe for backup`：`bin/codearts → bin/codearts.delete`；
   - 23:43:19 `installer extracted to temp dir`、`temp file cleaned up`；
   - **此后再无任何 upgrade 日志与报错** —— 部署（落盘 `bin/codearts`）静默失败，新版从未就位。
2. **网络层不稳定（旁证）**。10-30 20:20 的一次自动升级尝试下载同一安装包时 `ECONNRESET`（`service=domain-switch.cb-status "CB network error detected"`）；另有 OBS 主机 TLS 握手成功但 HTTP 0 字节悬挂（`codeheck-chajian-bj4-obs...` 实测 15s 超时）、`snap-access...` 间歇超时。
3. **跨 ZFS 数据集 rename 必失败（机制旁证）**。`/tmp` 与 `/home/wsc` 分属两个 ZFS 数据集（st_dev 29 vs 52），现场实测 `os.rename('/tmp/…','/home/…')` 报 `OSError [Errno 18] Invalid cross-device link`。若升级部署步骤用原生 rename 从 /tmp 迁移文件到 home，必然失败且可能被静默吞掉（与第 1 点现象吻合）。
4. **残局不可自愈**：旧二进制已被改名为 `.delete`，新版未落盘；此后任何新会话都找不到 CLI。工作台错误提示路径 `~/.codeartsdoer/installers/bin/codearts` 与代码一致（`src/environment.cpp resolveExecutable`）。
5. 手动 `codearts upgrade` 另有一条独立失败路径：缺 `CODEARTS_CLI_AK/CODEARTS_CLI_SK` 环境变量时直接报"认证失败"（实测输出原文：`认证失败，没有设置环境变量CODEARTS_CLI_AK/CODEARTS_CLI_SK`，指引 https://codearts.huaweicloud.com/portal/settings/cli-auth）。

### 2.3 损坏文件完整性核验（修复前提）
- `codearts.delete`：ELF64、`--version` = **26.10.9**、`--help` 正常、mode 755 —— 即升级前可用版本（与 codeartsGUI v0.2.6 CHANGELOG 验证过的"新 TUI 26.10.9"一致），**非半截文件**。
- `/tmp/agentkernel`（另一处升级残留，10-29 09:23）：实测 `--version` = 26.10.13，mode 600（无执行位、未部署）。

## 六、经验总结（高复用）

1. **"先改名后部署"的升级实现是危险模式**：改名与部署之间任何失败都会留下不可启动状态；防御：升级前对既有二进制做独立备份副本（本次 `codearts.bak-26.10.9`），或改用"新文件先落盘→原子替换"。
2. **跨 ZFS 数据集（/tmp 与 $HOME 分属不同 dataset）不能用 rename 迁移文件**：`EXDEV` 必现；跨文件系统移动一律用 copy+fsync+替换。本机环境下涉及 /tmp ↔ /home 的脚本/工具都要注意。
3. **"缺失即改名残留"排查捷径**：升级中断后优先 `ls` 安装 bin 目录找 `*.delete/*.old/*.bak`；`file`/`--version` 快速判断残留文件是否完整可复用。
4. **静态 Qt 在 Wayland 桌面报 `Could not find the Qt platform plugin "wayland"` 属预期降级**（xcb 插件 + XWayland），不要被该日志误导。
5. **见 `~/.codeartsdoer/cli-data/log/kernel-*.log`**：内核结构化日志（`service=upgrade` 等）是排障第一手证据，文件名含启动时间与 PID，可按时间窗精确定位事件。
